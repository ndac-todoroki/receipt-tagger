## 2026-10-26 店の検索手段

- 当初は検索APIで店の概要テキストを取り、分類モデルで店ジャンルにする設計だった
- 調べると Bing Search API は2025年に終了、Google Custom Search JSON API は新規登録不可で、残る Brave・Google Places はクレジットカード登録が必要だった
- 対処: 登録不要・無料の OpenStreetMap（Nominatim）で店名を検索し、店種別タグ（`shop=convenience` 等）を対応表で店ジャンルに変換する方式に変えた
- つまずき: 同名の店が複数ヒットし、`landuse=retail` や `highway=footway` も混ざる → 店に関係するカテゴリだけに絞り、ヒットした各タグの多数決で決めて、最多票の割合を信頼度にした

## 2026-10-30 OCRモデルの選定

- 候補: RapidOCR（PaddleOCR の ONNX 版、Apache-2.0、CPUで動く）の PP-OCRv5 server と PP-OCRv6 medium
- 3枚で比べると、v5 server は漢字が簡体字になり（例: 証→证、話→话）、片仮名も崩れた（ン→ソ）。v6 medium は日本語として正しく読め、ロゴの店名も読めることがあった → v6 medium を採用
- 処理時間は DGX Spark の CPU で1枚あたり約4〜13秒
- 残る誤読の癖: 金額のカンマがピリオドになる、¥ が * になる、軽減税率の印（J・軽）が数字に付く → パーサ側で吸収する

## 2026-10-30 品目抽出のベースライン

- 実物を見ると、店名がロゴ画像で文字になっていないレシートが多い。代わりに「事業者名：株式会社〜」の行が文字で入っていることが多いので、これを店名の最優先の候補にした
- ルールのパーサ（日付の行と小計・合計の行で区切る）で89枚を処理した結果:

| 指標 | 値 |
|---|---|
| 合計金額を読めた | 53 / 89（60%） |
| 合計整合（品目の合計 = 小計・合計・合計−外税のいずれか） | 18 / 89（20%） |
| 品目が1つ以上取れた | 67 / 89（75%） |
| 店名の候補が1つ以上出た | 85 / 89（96%） |

- 目標の合計整合率80%には遠い。失敗の内訳を見て改善する

### 改善1: 行の組み立てが崩れていた

- 失敗の内訳を見ると、レシート全体が2〜3行にまとまってしまっているものが多かった
- 原因: 箱を直前の箱とだけ比べていたため、少し傾いた写真で左右の列の箱が交互に並び、少しずつずれながら鎖のように全部つながっていた
- 対処: 箱の上辺の傾きの中央値から写真の傾きを見積もって打ち消し、比べる相手を行全体の平均位置にした。しきい値もロゴなど大きな箱に引きずられないよう箱の高さの中央値から決めた
- 結果: 合計を読めた 60% → 72%、合計整合 20% → 35%、品目が取れた 75% → 83%

### 改善2: 品目と合計の読み取りルール

- 合計が合わないレシートを見て、次の誤りを直した
  - レジ担当者名とレジ番号の行（例: 名前 + 4桁の数字）を品目と読んでいた → 品目の金額の多くに ¥ などの印が付くレシートでは、印の無い数字を金額とみなさない
  - 住所のハイフン（「26-6」）を値引きのマイナスと読んでいた → 語に続くハイフンは符号とみなさない。住所の行は品目にしない
  - 印字の位置のずれで、前の品目の金額が次の品目のJANコードと同じ行に読まれていた → JANの行の金額は直前の品名に付ける
  - 「¥0」が「04」と読まれていた → 0で始まる数字は金額とみなさない
  - 税率ごとの消費税の内訳と「外税額計」を二重に足していた → 合計行があればそれだけを使う
  - 「730円」「¥1,000-」の形や、「合計」が無く「支払金額」だけのレシートに対応した
- 結果: 合計を読めた 72% → 76%、合計整合 35% → 49%

## 2026-10-30 品目ジャンル分類（学習なし）

- 日本語の埋め込みモデル Ruri v3 30m（Apache-2.0、CPUで動く）で、品名とジャンルごとの見本の品名との類似度を取り、最も近い見本のジャンルにする
- パーサが取り出した369品で試すと、目視で半分強は妥当。ほろよい（酎ハイ）→その他食品、ウイスキー銘柄→食材、カップ麺→雑貨のような、商品名だけでは種類が分からないものを外しやすい
- つまずき: 温度0.05では、正しいジャンルでも信頼度が0.2〜0.4に留まり、ほぼすべて「未確定」になった。Ruri の類似度は狭い範囲に集まるため。0.02に下げると閾値0.5以上が25%（暫定。正解ラベルを作ってから決め直す）
- つまずき: コンビニなど半角カナのレシートで、濁点・半濁点が引用符や度の記号に読まれていた（ト” → ド）→ パーサで仮名の直後の記号を濁点に戻した
